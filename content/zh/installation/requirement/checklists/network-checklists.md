## 网络架构

### 规划

- **拓扑**
 验证架构（星型/环型/网状）是否满足高可用要求。
- **冗余**
 确保节点之间至少有两条独立的物理链路。
- **带宽**
 计算预估流量：对象存储读写带宽 × 节点数 × 副本数 + 20% 冗余。

### IP 分配

- [ ] 将管理网络与数据网络分离。
- [ ] 为存储节点分配连续的 IP 地址段（推荐 /24 子网）。
- [ ] 至少预留 15% 的 IP 地址用于扩容。

## 硬件要求

### 交换机

| 检查项 | 要求 |
|--------|---------|
| 背板带宽 | ≥ 全端口线速转发能力 × 1.2 |
| 端口类型 | 10G/25G/100G SFP+/QSFP+ 光纤端口 |
| 流表容量 | ≥ 节点数 × 5 |
| 生成树 | 启用 RSTP/MSTP 快速收敛 |

### 布线

- [ ] 光纤衰减测试（单模 ≤0.35dB/km）。
- [ ] 端口错位检查（节点 A eth0 ↔ 节点 B eth0）。
- [ ] 线缆标签（包括源/目标 IP + 端口号）。

## 操作系统配置

### 内核调优

```bash
# Check the following parameter settings
net.core.rmem_max = 16777216
net.core.wmem_max = 16777216
net.ipv4.tcp_keepalive_time = 600
net.ipv4.tcp_slow_start_after_idle = 0
```

### 网卡配置

- [ ] 启用巨型帧（MTU=9000，需要全路径支持）。
- [ ] 验证绑定模式（推荐 LACP mode4）。
- [ ] 禁用 IPv6（如不需要）。

## 安全性

### 防火墙

```text
# Necessary open ports
- TCP 9000 (S3 API; also used for internal node-to-node communication)
- TCP 9001 (RustFS Console)
- TCP 443 (only if you terminate HTTPS on a reverse proxy / load balancer)
```

### 访问控制

- 交换机端口安全 MAC 限制。
- 存储节点之间使用 IPSec 隧道加密。
- 为管理界面启用 TLS 1.3。

## 性能测试

### 基准测试

1. 节点间延迟：`ping -c 20 <target IP>`（吞吐量测试需先在目标端运行 `iperf3 -s`）
2. 跨机架带宽：`iperf3 -c <target IP> -P 8 -t 30`
3. 故障转移：随机断开核心链路，观察恢复时间。

### 标准

| 指标 | 要求 |
|------|------|
| 节点延迟 | ≤1ms（同一机房）/ ≤5ms（跨可用区） |
| 带宽利用率 | 峰值 ≤ 设计容量的 70% |
| 故障转移 | BPDU 收敛时间 < 500ms |

## 文档要求

1. 网络拓扑图（包括物理连接和逻辑 IP）
2. 交换机配置备份文件（带时间戳）
3. 基准测试报告（包括原始数据）
4. 变更记录表（包括维护窗口信息）

:::tip

建议正式部署前进行 72 小时压力测试，模拟峰值流量 110% 的负载场景。

:::

此清单涵盖企业存储系统网络部署的关键检查点，并针对分布式对象存储的特点提供优化参数要求。你可以联系 RustFS 获取官方技术支持。
