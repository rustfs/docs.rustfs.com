---
title: "Installer RustFS avec Helm"
description: Installez RustFS en mode autonome ou distribué sur Kubernetes avec le chart Helm officiel.
---

Ce guide récupère le chart RustFS officiel depuis les sources ou le dépôt Helm, l’installe et vérifie l’accès à l’API S3 et à la Console.

## Prérequis

| Composant | Exigence |
|-----------|-------------|
| Helm | Version 3 |
| Kubernetes | Un cluster accessible avec `kubectl` |
| StorageClass | Provisionnement dynamique de PVC pour les données RustFS |
| RustFS | `1.0.0-alpha.69` ou ultérieur |

Un contrôleur Ingress est facultatif. Si vous activez l’Ingress, définissez `ingress.className` sur le contrôleur présent dans votre cluster, par exemple `nginx` ou `traefik`.

Vérifiez le cluster actif et les StorageClasses disponibles :

```bash
kubectl config current-context
kubectl get storageclass
helm version --short
```

## 1. Obtenir le chart

Choisissez comment Helm doit accéder au chart. Les deux options définissent `RUSTFS_CHART`, que les commandes d’installation ci-dessous utilisent.

<Tabs items={["Cloner le dépôt", "Dépôt Helm"]} updateAnchor={false}>
  <Tab value="Cloner le dépôt" id="helm-chart-clone">

Clonez le dépôt source de RustFS afin d’utiliser le chart situé dans `helm/rustfs` :

```bash
git clone https://github.com/rustfs/rustfs.git
cd rustfs
export RUSTFS_CHART=./helm/rustfs
```

  </Tab>
  <Tab value="Dépôt Helm" id="helm-chart-repository">

Ajoutez le dépôt RustFS indiqué sur [Artifact Hub](https://artifacthub.io/packages/helm/rustfs/rustfs), puis mettez à jour l’index du dépôt local :

```bash
helm repo add rustfs https://charts.rustfs.com
helm repo update
export RUSTFS_CHART=rustfs/rustfs
```

  </Tab>
</Tabs>

## 2. Installer le mode autonome

Créez un fichier de valeurs pour un déploiement de développement à un seul pod :

```yaml title="standalone-values.yaml"
mode:
  standalone:
    enabled: true
  distributed:
    enabled: false

secret:
  rustfs:
    access_key: "<your-access-key>"
    secret_key: "<your-secret-key>"

storageclass:
  name: standard
  dataStorageSize: 10Gi
  logStorageSize: 1Gi

ingress:
  enabled: false
```

Remplacez `standard` par une StorageClass de votre cluster, puis installez :

```bash
helm upgrade --install rustfs "$RUSTFS_CHART" \
  --namespace rustfs \
  --create-namespace \
  -f standalone-values.yaml
```

## 3. Installer le mode distribué

Pour un cluster distribué, définissez explicitement le nombre de pods et le nombre de disques. Le nombre total de disques de données est égal à `replicaCount * drivesPerNode`.

```yaml title="distributed-values.yaml"
mode:
  standalone:
    enabled: false
  distributed:
    enabled: true

replicaCount: 4
drivesPerNode: 2

secret:
  rustfs:
    access_key: "<your-access-key>"
    secret_key: "<your-secret-key>"

storageclass:
  name: standard
  dataStorageSize: 100Gi
  logStorageSize: 1Gi

ingress:
  enabled: false
```

L’exemple crée quatre pods et huit PVC de données. Assurez-vous que le cluster peut planifier tous les pods et provisionner tous les PVC, puis installez :

```bash
helm upgrade --install rustfs "$RUSTFS_CHART" \
  --namespace rustfs \
  --create-namespace \
  -f distributed-values.yaml
```

:::warning[Choisissez la topologie avant l’installation]

Kubernetes n’autorise pas la modification des `volumeClaimTemplates` d’un StatefulSet. Modifier `drivesPerNode` ultérieurement exige de recréer le StatefulSet ou de procéder à une nouvelle installation.

:::

## 4. Vérifier RustFS et y accéder

```bash
kubectl -n rustfs get pods,pvc,services
kubectl -n rustfs rollout status statefulset/rustfs
```

Le mode autonome crée un Deployment à la place d’un StatefulSet. Vérifiez-le avec :

```bash
kubectl -n rustfs rollout status deployment/rustfs
```

Redirigez l’API S3 et la Console vers votre poste de travail :

```bash
kubectl -n rustfs port-forward svc/rustfs 9000:9000 9001:9001
```

Utilisez `http://localhost:9000` comme point de terminaison S3 et ouvrez `http://localhost:9001` pour la Console.

## Valeurs principales

| Valeur | Rôle | Valeur par défaut du chart |
|-------|---------|---------------|
| `mode.standalone.enabled` | Active le mode autonome à un seul pod | `false` |
| `mode.distributed.enabled` | Active le mode distribué | `true` |
| `replicaCount` | Nombre de pods en mode distribué | `4` |
| `drivesPerNode` | PVC de données par pod | Déduit de `replicaCount` |
| `storageclass.name` | StorageClass des PVC | `local-path` |
| `storageclass.dataStorageSize` | Taille de chaque PVC de données | `256Mi` |
| `storageclass.logStorageSize` | Taille de chaque PVC de journaux | `256Mi` |
| `service.endpoint.port` | Port de l’API S3 | `9000` |
| `service.console.port` | Port de la Console | `9001` |

Nous recommandons de définir explicitement les tailles de stockage ; les valeurs par défaut du chart sont destinées uniquement à une évaluation de base.
