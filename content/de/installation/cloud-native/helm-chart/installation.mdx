---
title: "RustFS mit Helm installieren"
description: Installieren Sie RustFS im Standalone- oder verteilten Modus mit dem offiziellen Helm-Chart auf Kubernetes.
---

Diese Anleitung bezieht das offizielle RustFS-Chart aus dem Quellcode oder dem Helm-Repository, installiert es und prüft den Zugriff auf die S3-API und die Console (Weboberfläche).

## Anforderungen

| Komponente | Anforderung |
|-----------|-------------|
| Helm | Version 3 |
| Kubernetes | Ein mit `kubectl` erreichbarer Cluster |
| StorageClass | Dynamische PVC-Bereitstellung für RustFS-Daten |
| RustFS | `1.0.0-alpha.69` oder neuer |

Ein Ingress-Controller ist optional. Wenn Sie Ingress aktivieren, setzen Sie `ingress.className` auf den Controller in Ihrem Cluster, zum Beispiel `nginx` oder `traefik`.

Prüfen Sie den aktiven Cluster und die verfügbaren StorageClasses:

```bash
kubectl config current-context
kubectl get storageclass
helm version --short
```

## 1. Chart beziehen

Wählen Sie, wie Helm auf das Chart zugreift. Beide Optionen setzen `RUSTFS_CHART`, das die Installationsbefehle weiter unten verwenden.

<Tabs items={["Repository klonen", "Helm-Repository"]} updateAnchor={false}>
  <Tab value="Repository klonen" id="helm-chart-clone">

Klonen Sie das RustFS-Quell-Repository, um das Chart unter `helm/rustfs` zu verwenden:

```bash
git clone https://github.com/rustfs/rustfs.git
cd rustfs
export RUSTFS_CHART=./helm/rustfs
```

  </Tab>
  <Tab value="Helm-Repository" id="helm-chart-repository">

Fügen Sie das auf [Artifact Hub](https://artifacthub.io/packages/helm/rustfs/rustfs) aufgeführte RustFS-Repository hinzu und aktualisieren Sie anschließend den lokalen Repository-Index:

```bash
helm repo add rustfs https://charts.rustfs.com
helm repo update
export RUSTFS_CHART=rustfs/rustfs
```

  </Tab>
</Tabs>

## 2. Standalone-Modus installieren

Legen Sie eine Values-Datei für eine Entwicklungsumgebung mit einem Pod an:

```yaml title="standalone-values.yaml"
mode:
  standalone:
    enabled: true
  distributed:
    enabled: false

secret:
  rustfs:
    access_key: "<your-access-key>"
    secret_key: "<your-secret-key>"

storageclass:
  name: standard
  dataStorageSize: 10Gi
  logStorageSize: 1Gi

ingress:
  enabled: false
```

Ersetzen Sie `standard` durch eine StorageClass in Ihrem Cluster und installieren Sie anschließend:

```bash
helm upgrade --install rustfs "$RUSTFS_CHART" \
  --namespace rustfs \
  --create-namespace \
  -f standalone-values.yaml
```

## 3. Verteilten Modus installieren

Setzen Sie für einen verteilten Cluster die Anzahl der Pods und Laufwerke ausdrücklich. Die Gesamtzahl der Datenlaufwerke entspricht `replicaCount * drivesPerNode`.

```yaml title="distributed-values.yaml"
mode:
  standalone:
    enabled: false
  distributed:
    enabled: true

replicaCount: 4
drivesPerNode: 2

secret:
  rustfs:
    access_key: "<your-access-key>"
    secret_key: "<your-secret-key>"

storageclass:
  name: standard
  dataStorageSize: 100Gi
  logStorageSize: 1Gi

ingress:
  enabled: false
```

Das Beispiel erzeugt vier Pods und acht Daten-PVCs. Stellen Sie sicher, dass der Cluster alle Pods einplanen und alle PVCs bereitstellen kann, und installieren Sie anschließend:

```bash
helm upgrade --install rustfs "$RUSTFS_CHART" \
  --namespace rustfs \
  --create-namespace \
  -f distributed-values.yaml
```

:::warning[Topologie vor der Installation festlegen]

Kubernetes erlaubt keine Aktualisierung der `volumeClaimTemplates` eines StatefulSet. Eine spätere Änderung von `drivesPerNode` erfordert, dass das StatefulSet neu angelegt oder die Installation neu ausgeführt wird.

:::

## 4. RustFS prüfen und erreichen

```bash
kubectl -n rustfs get pods,pvc,services
kubectl -n rustfs rollout status statefulset/rustfs
```

Der Standalone-Modus erzeugt ein Deployment anstelle eines StatefulSet. Prüfen Sie es mit:

```bash
kubectl -n rustfs rollout status deployment/rustfs
```

Leiten Sie die S3-API und die Console auf Ihre Arbeitsstation weiter:

```bash
kubectl -n rustfs port-forward svc/rustfs 9000:9000 9001:9001
```

Verwenden Sie `http://localhost:9000` als S3-Endpunkt und öffnen Sie `http://localhost:9001` für die Console.

## Wichtige Values

| Wert | Zweck | Chart-Standard |
|-------|---------|---------------|
| `mode.standalone.enabled` | Standalone-Modus mit einem Pod aktivieren | `false` |
| `mode.distributed.enabled` | Verteilten Modus aktivieren | `true` |
| `replicaCount` | Anzahl der Pods im verteilten Modus | `4` |
| `drivesPerNode` | Daten-PVCs pro Pod | Aus `replicaCount` abgeleitet |
| `storageclass.name` | StorageClass für PVCs | `local-path` |
| `storageclass.dataStorageSize` | Größe jedes Daten-PVC | `256Mi` |
| `storageclass.logStorageSize` | Größe jedes Protokoll-PVC | `256Mi` |
| `service.endpoint.port` | Port der S3-API | `9000` |
| `service.console.port` | Console-Port | `9001` |

Wir empfehlen, Speichergrößen ausdrücklich zu setzen. Die Chart-Standards sind nur für eine grundlegende Evaluierung gedacht.
